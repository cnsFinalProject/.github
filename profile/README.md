# CNS Final Project

**프로젝트의 코드, 설계, 설정을 함께 관리하는 팀 개발 공간**

[프로젝트 문서](https://github.com/cnsFinalProject/platform) · [Backend](https://github.com/cnsFinalProject/Backend) · [FrontEnd](https://github.com/cnsFinalProject/FrontEnd)

## 프로젝트 소개
현재 프로젝트 저장소와 협업 문서의 초기 구조를 준비하고 있습니다.
서비스명, 해결할 문제, 대상 사용자, 주요 기능은 요구사항 합의 후 아래 문서에서 관리합니다.

## 저장소
| 저장소 | 역할 |
| --- | --- |
| [platform](https://github.com/cnsFinalProject/platform) | 수행계획, 요구사항, 아키텍처, API 계약, 데이터 설계, 테스트 및 의사결정 |
| [Backend](https://github.com/cnsFinalProject/Backend) | 백엔드 코드 및 실행 안내 |
| [FrontEnd](https://github.com/cnsFinalProject/FrontEnd) | 프론트엔드 코드 및 실행 안내 |
| [config-repo](https://github.com/cnsFinalProject/config-repo) | 환경별 설정 구조와 설정 예제 |
| [.github](https://github.com/cnsFinalProject/.github) | 조직 소개 및 공통 이슈·PR 템플릿 |
| [FrontTest](https://github.com/cnsFinalProject/FrontTest) | 기존 테스트 저장소 |

## 시작하기
1. [프로젝트 계획](https://github.com/cnsFinalProject/platform/blob/main/docs/planning/project-plan.md)과 [요구사항](https://github.com/cnsFinalProject/platform/blob/main/docs/requirements/requirements.md)을 작성합니다.
2. [아키텍처](https://github.com/cnsFinalProject/platform/blob/main/docs/architecture/overview.md), [API 계약](https://github.com/cnsFinalProject/platform/blob/main/docs/contracts/api-spec.md), [데이터 설계](https://github.com/cnsFinalProject/platform/blob/main/docs/data/table-spec.md)를 합의합니다.
3. 작업 이슈를 만들고 PR에 변경 내용과 검증 결과를 기록합니다.

## 팀과 진행 상태
- 팀원 및 역할: [프로젝트 계획](https://github.com/cnsFinalProject/platform/blob/main/docs/planning/project-plan.md)에서 작성합니다.
- 진행 상황: 각 저장소의 Issues와 Pull Requests에서 확인합니다.
- 현재 단계: 저장소 및 문서 틀 구성. 애플리케이션과 배포 환경은 아직 구현하지 않았습니다.

## 협업 방식
[개발 가이드](https://github.com/cnsFinalProject/.github/blob/main/CONTRIBUTING.md)를 따르고, 서비스 간 변경은 platform 문서에 기록합니다.
